# .gitignore

## Purpose

The `.gitignore` file specifies which files and directories should be excluded from git version control. This prevents committing build artifacts, dependencies, IDE files, and other files that shouldn't be tracked.

## Ignored Patterns

### Dependencies
- **node_modules/**
  - npm/yarn/pnpm installed packages
  - Should be installed via `npm install`, not committed
- **pnpm-lock.yaml**, **package-lock.json**, **yarn.lock**
  - Lock files from different package managers
  - Only one should be committed (project uses npm)

### Build Output
- **dist/**
  - Compiled JavaScript output from TypeScript
  - Generated files, should be built from source
- ***.tsbuildinfo**
  - TypeScript incremental build information
  - Cache file for faster subsequent builds

### IDE Files
- **.vscode/**
  - Visual Studio Code workspace settings
  - User-specific IDE configuration
- **.idea/**
  - JetBrains IDE (WebStorm, IntelliJ) configuration
  - User-specific IDE settings
- ***.swp**, ***.swo**, ***~**
  - Vim/Emacs swap and backup files
  - Temporary editor files

### Operating System Files
- **.DS_Store**
  - macOS Finder metadata file
  - System-specific, not needed in repo
- **Thumbs.db**
  - Windows thumbnail cache file
  - System-specific, not needed in repo

### Application State
- **.pushguard/.state.json**
  - Temporary state file (overrides, rate limiting)
  - Gitignored by design - contains user-specific runtime state
  - Should not be committed as it's ephemeral

### Environment Variables
- **.env**, **.env.local**
  - Environment variable files
  - May contain API keys and secrets
  - Should never be committed for security

### Logs
- ***.log**
  - Log files from various tools
- **npm-debug.log***
  - npm error logs
  - Debugging information, not needed in repo

## Security Considerations

This `.gitignore` file helps prevent:
- **API Keys**: Environment files with secrets are excluded
- **User State**: Runtime state files are excluded
- **Build Artifacts**: Only source code is tracked

## Usage

Git automatically respects this file when:
- Running `git add` (ignored files are skipped)
- Running `git status` (ignored files don't appear)
- Running `git commit` (ignored files are not included)

## Notes

- The `.pushguard/.state.json` file is intentionally gitignored because it contains temporary runtime state that varies per user and execution
- The `.pushguard/config.yml` file is NOT gitignored, so it can be committed to share configuration with the team
- Build output (`dist/`) is ignored because it's generated from source files
